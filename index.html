Capital One · GenAI platform

GenAI ETL Automation Platform

5 mo → 4 wk

delivery time, with 70%+ less engineering effort

Translates English business rules and metadata into production-ready PySpark and Scala, deployable as AWS Glue jobs, so teams can build ETL workflows without hand-writing code.

  1. a.Two-phase design: an LLM translates pseudocode into code, then a deterministic orchestration engine assembles and executes the pipeline.
  2. b.Models each ETL job as a dependency graph so runs are fault-tolerant and lineage-aware.
  3. c.Agentic RAG with few-shot and Chain-of-Thought prompting, plus automated validation and feedback-driven retry loops.
  4. d.Led benchmarking of open models on latency, accuracy, reasoning quality, hallucination rate and cost to choose the production model.
  5. e.Load-tested the platform to set throughput, latency and reliability targets.

Capital One · Agentic AI

Conversion Mapping Intelligence Engine

75%

source-field recall on cross-domain benchmarks

A human-in-the-loop agent for a large enterprise data migration. It proposes source-to-target data mappings, critiques and refines them, and hands them to a person for approval.

How it works

  • –Follows the ReAct pattern: the agent reasons, calls tools, reads the results and revises its mapping.
  • –Grounds its answers in requirements and knowledge from past conversions.
  • –Uses enterprise data-catalog, knowledge-search and data-query tools through MCP.

How it's evaluated

  • –Benchmarked across domains, comparing models, reasoning settings and prompt versions.
  • –Tuned prompts from the results and built feedback loops that feed evaluation back into the agent.

⟶Pairs with the GenAI ETL platform (01): approved mappings are the kind of input it turns into code.

§02How I build02 / 06

A personal agent platform

Outside work, I run a small self-hosted agent platform for my own automations. No single task is the point. It's where I work out the patterns that make agents safe to leave running: isolation, independent verification and a human approval step.

Principles I build agents by

  1. 01

    Treat inputs as untrusted

    Anything that comes from the web is data, not instructions. Runs are sandboxed so a prompt injection has nothing to reach.

  2. 02

    Verify outside the model

    LLM output passes through an independent judge and deterministic checks before anything is saved.

  3. 03

    Bound every run

    Time limits and dollar caps on each job, so a runaway agent fails cleanly instead of burning budget.

  4. 04

    Keep the surface small

    Only a few routes are public. Admin tools listen on loopback only, and the extension can't reach other sites.

  5. 05

    Spec first, then test

    Every change starts as an OpenSpec proposal and ships with tests, including end-to-end runs in a real browser.
